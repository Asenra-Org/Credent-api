## 1. Task Overview

### What is this task? (Beginner-friendly)

When a credit officer uploads a financial document (e.g., a bank statement or audit report), the system automatically scans the PDF using a forensics tool called **pikepdf**. If the scan detects that the PDF was created or edited using a suspicious tool — like Adobe Photoshop, Canva, or Nitro PDF — it sets a flag: `is_suspicious = True`.

Before this ticket, that flag was displayed in the API response but had **no effect** on the credit score. The borrower would still receive the same base score even if their document was clearly tampered with.

**This ticket fixes that.** When tampering is detected, the base credit score is automatically reduced by exactly **15 points** — creating a direct, deterministic, rule-based penalty inside the credit scoring pipeline.

## 2. Existing Architecture

The CREDENT scoring pipeline processes uploaded documents in the following order:

```

   ├── Text cleaning
   └── Returns { text: str, tables_count: int }
             │
             ▼
DocumentIngestionAgent.parse_financial_statement()
   ├── Sends text to Groq LLM (llama-3.1-8b-instant)
   ├── Extracts: company_name, sector, revenue, debt, etc.
   └── Returns ai_analysis dict with base_score: int (0-100)
             │
             ▼
[AI-A-W4] apply_forensics_penalty()  ← NEW — this ticket
   ├── Reads forensics["is_suspicious"]
   ├── If True: deducts 15 from base_score (floor at 0)
   └── Writes adjusted base_score back into ai_analysis
             │
             ▼
```

The financial health score (`FinancialHealthAgent.financial_health_score`) is a **separate pipeline** served by `/api/v1/analysis/financial-health` and is completely unaffected by this change.

## 3. How pikepdf Forensics Works

`run_pdf_forensics()` uses the **pikepdf** library to inspect the internal metadata of a PDF file:

```python
with pikepdf.Pdf.open(file_path) as pdf:
    meta = pdf.docinfo
    creator  = meta.get('/Creator', 'Unknown')   # Software that created the PDF
    producer = meta.get('/Producer', 'Unknown')  # Software that exported/printed it
    mod_date      = meta.get('/ModDate', '')      # Last modification timestamp
    creation_date = meta.get('/CreationDate', '') # Original creation timestamp
```

**Suspicion is triggered if:**
1. `/Creator` or `/Producer` contains a suspicious tool name: `photoshop`, `illustrator`, `canva`, `nitro`, `gimp`, `inkscape`
2. `/ModDate != /CreationDate` — meaning the document was modified after originally created

Both conditions independently set `is_suspicious = True` and append a human-readable flag to the `flags` list.

---

## 4. What `is_suspicious` Means

`is_suspicious` is a **sentinel field** — a boolean that summarizes the entire forensics scan result into a single actionable signal. It means:

> "Based on PDF metadata analysis, this document shows signs of having been created or edited using software that is not consistent with legitimate financial document production."

It does **not** prove fraud. It is a **risk signal** that warrants a score reduction:
- A genuine bank statement is generated by core banking software (e.g., Finacle, Temenos).
- A PDF claiming to be a bank statement but created in Photoshop is suspicious by definition.

## 5. Credit Scoring Flow (After AI-A-W4)

```
base_score (LLM estimated)    =  80
is_suspicious (forensics)     =  True
FORENSICS_PENALTY             =  15

apply_forensics_penalty():
    adjusted_score = max(0, 80 - 15) = 65

ai_analysis["base_score"] <- 65   (written back before response)
forensics_penalty = {
    original_score: 80,
    adjusted_score: 65,
    penalty_applied: True,
    penalty_points: 15
}
```

## 6. Why a 15-Point Penalty Was Chosen

The ticket specification states: **"deduct exactly 15 points."** This is a product/risk policy decision, not an engineering one.

- 15 points is approximately **15% of the 0-100 scale** — meaningful but not catastrophic.
- It aligns with the range used by `RiskIntelligenceAgent` (±10 to ±30 pts for qualitative notes).
- Stored as `FORENSICS_PENALTY = 15` — one place for the risk team to update it without searching for magic numbers.

## 8. Explanation of Every Code Change

### 8.1 `FORENSICS_PENALTY: int = 15`

Module-level constant after `router` definition. Allows tests to `import FORENSICS_PENALTY` and assert its value. Type annotation prevents float assignment.

### 8.2 `apply_forensics_penalty(base_score, forensics_result) -> dict`

**Pure function.** Four defensive steps:

**Step 1 — Normalise base_score:**
```python
try:
    safe_score: int = max(0, int(base_score))
except (TypeError, ValueError):
    safe_score = 0
```
Converts floats and numeric strings; catches None (TypeError) and non-numeric strings (ValueError). Clamps to 0.

**Step 2 — Guard against bad forensics_result:**
```python
if not forensics_result or not isinstance(forensics_result, dict):
    return _no_penalty
```
Catches None, empty dict, wrong types.

**Step 3 — Extract and validate `is_suspicious`:**
```python
raw_flag = forensics_result.get("is_suspicious")
if raw_flag is None:
    return _no_penalty
is_suspicious: bool = bool(raw_flag)
```
Uses `.get()` for absent keys; `bool()` for truthy/falsy coercion.

**Step 4 — Apply penalty with floor:**
```python
adjusted: int = max(0, safe_score - FORENSICS_PENALTY)
```
Single subtraction ensures penalty applied exactly once; `max(0, ...)` prevents negative scores.

### 8.3 Call site in `ingest_pdf_document()`

```python
forensics_penalty = apply_forensics_penalty(
    base_score=ai_analysis.get("base_score", 0),
    forensics_result=forensics,
)
ai_analysis["base_score"] = forensics_penalty["adjusted_score"]
```

Placed after `parse_financial_statement()` — the only moment both `forensics` and `ai_analysis` are in scope. `ai_analysis["base_score"]` is updated in-place; downstream consumers always see the adjusted value.

### 8.4 New response key

```python
"forensics_penalty": forensics_penalty,  # additive — nothing removed
```

## 9. Edge Cases Handled

| Scenario | Behaviour |
|---|---|
| `forensics_result = None` | Returns `_no_penalty` (safe-fail) |
| `forensics_result = {}` | `is_suspicious` absent → `_no_penalty` |
| `is_suspicious` key absent | `.get()` returns `None` → `_no_penalty` |
| `is_suspicious = None` | Explicit `None` check → `_no_penalty` |
| `is_suspicious = 1` (truthy int) | `bool(1) == True` → penalty applied |
| `is_suspicious = 0` (falsy int) | `bool(0) == False` → no penalty |
| `forensics_result` is a list/string/int | `isinstance(..., dict)` fails → `_no_penalty` |
| `base_score = None` | `int(None)` → TypeError → `safe_score = 0` |
| `base_score = "abc"` | `int("abc")` → ValueError → `safe_score = 0` |
| `base_score = 5` (< 15) | `max(0, 5-15)` → `0` |
| `base_score = 0` | `max(0, 0-15)` → `0` |
| `base_score = 15` (exactly) | `max(0, 15-15)` → `0` |
| Multiple flags in forensics | `is_suspicious` is one bool → penalty applied once |

## 12. Time & Space Complexity

`apply_forensics_penalty()`:
- **Time: O(1)** — dictionary lookups and arithmetic only. No loops, no sorting.
- **Space: O(1)** — returns a fixed-size 4-key dict.

The function adds **zero measurable latency** to the `/ingest/pdf` route, already dominated by LLM inference (2–10 seconds).

## 13. Beginner-Friendly Revision Notes

**Q: Why is `apply_forensics_penalty` a separate function and not inline in the route?**
A: A named function can be imported and tested directly without needing a real PDF, a server, or any mocks.

**Q: What is a "pure function"?**
A: Same output for same input; no side effects (no file writes, no DB calls, no global state changes). Predictable and testable.

**Q: Why mock `run_pdf_forensics` in tests instead of providing a real PDF?**
A: Real PDFs require real files; we can't control what pikepdf finds. Mocking isolates the penalty logic from the scanner, which has its own tests.

**Q: Why is `FORENSICS_PENALTY` a module constant, not a function parameter?**
A: It is a business policy decision. A parameter would let callers pass any value, creating inconsistency. A constant enforces uniformity across all call sites.

## 14. Interview Questions Related to This Implementation

**Q1: Why is the penalty applied at the route layer rather than inside the agent?**
> The route handler is the convergence point where both `forensics` and `ai_analysis` exist simultaneously. Placing it in either agent would introduce coupling between two independent subsystems.

**Q2: What happens if pikepdf crashes and never returns a forensics dict?**
> `run_pdf_forensics()` has a `try/except` catching all exceptions and returning `is_suspicious=False`. Additionally, `apply_forensics_penalty()` guards against `None` and non-dict inputs.

**Q3: How do you ensure the penalty is applied exactly once?**
> The function is called exactly once per request. It performs a single subtraction. Multiple entries in `forensics["flags"]` have no effect — only `is_suspicious` (a single boolean) is read.

**Q4: What if the base_score is already 0 and tampering is detected?**
> `max(0, 0 - 15)` = `max(0, -15)` = `0`. Score stays at the floor. `penalty_applied=True` still records that a penalty was attempted.

**Q5: Why does the response include both `forensics` and `forensics_penalty` separately?**
> `forensics` preserves API backwards compatibility (raw scanner output). `forensics_penalty` is the scoring consequence. Separate keys let consumers inspect what was found AND how it affected the score independently.
